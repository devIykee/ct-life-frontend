## Audio change and why it is needed

Unity 6.3 hot reload preserves eligible instance fields, including private serializable fields; static state and unsupported serialized types are not restored. Dictionaries and readonly fields do not meet normal serialization rules. `OnDisable` is invoked when scripts reload, followed by `OnEnable`. Those documented behaviors match the collection and subscription lifecycle that this client must manage. [Serialization rules](https://docs.unity3d.com/6000.3/Documentation/Manual/script-serialization-rules.html), [hot reload serialization](https://docs.unity3d.com/6000.3/Documentation/Manual/script-serialization-how-unity-uses.html), [OnDisable](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/MonoBehaviour.OnDisable.html).

Changes authorized by root, now frozen in live source:

- `AudioManager.cs`: rebind static instance and existing named source children on enable; reconstruct eight SFX, two ambience and four footstep bindings; reload the map; recreate bus subscriptions once; restore player/camera listener selection. Serializable ambience fade state is retained. Disable stops transient voices, pauses ambience and releases subscriptions.
- `MusicDirector.cs`: serialize the bank state that identifies selected district, clips, gains and fade progress; reconstruct stem/filter dictionaries from existing named source children; retain two banks and exactly one director. Disable pauses selected music; enable resumes clips or reschedules a bank that had not yet started.
- Paused loops use Unity's documented `Pause` / `UnPause` behavior. Sources are reused, not recreated on every reload. There are new development assertions for restored bindings, exactly 26 source components and playing selected music. [Pause](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/AudioSource.Pause.html), [UnPause](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/AudioSource.UnPause.html).

Verification completed: `python3 client/Tools~/compile_check.py --editor` passed all assemblies after the lifecycle change; the audio assembly compiled again after adding assertions; targeted `git diff --check` passed. **Native reload behavior and Seeker behavior were not yet validated at this checkpoint.** No assertion was replaced by a catch-and-ignore path.
