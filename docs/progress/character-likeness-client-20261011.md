# Personal character client — 2026-10-11

Implemented the photo → reference approval → actual generated model review → server acceptance path. The white review sheet uses a bounded preview area, scrolling consent/status copy and fixed action area. All copy goes through `Strings`; the coordinator merged keys. Human-only entry is enforced by the parent creator and checked in the panel. Operator-evaluation jobs are explicitly labelled as using a synthetic face.

Android photo selection uses the system `ACTION_PICK_IMAGES` intent on API33+, `ACTION_OPEN_DOCUMENT` on older Android, with no broad media permission. A private wrapper Activity reads only the chosen URI, bounds compressed bytes and dimensions, samples to2048, corrects EXIF orientation, strips metadata by JPEG re-encoding and returns a temporary app-cache file. C# deletes the file after reading it. Photos remain in memory until upload/close. Every upload sends the versioned own-photo and Tripo-sharing consent headers. Source deletion and cancel are real authenticated endpoints. The Android Java source compiled with the installed Android35 SDK and JDK successfully; phone-picker behavior still requires coordinator testing.

The authenticated transport bounds all binary downloads before buffering beyond budget, rejects redirects, checks returned SHA256, ties requests to the signed-in owner and refreshes access before binary reads. Approval submits exactly the displayed reference hash. Job IDs and idempotency intent keys resume from local state plus the authoritative owned-job list; photos are not persisted in PlayerPrefs. Existing jobs remain resumable when new generation is disabled.

Checkout uses the dedicated likeness contract, not Cash top-up: server-priced quote, explicit price/network review, existing MWA transaction signer, submitted signature, finalized server receipt and owned entitlement. A signing-attempt marker and receipt keys are persisted before opening the wallet. An uncertain broadcast is reconciled without signing again. No retail price is invented. No wallet transaction or paid generation was executed by this client task. Retail is server-quoted at the user-selected 3 USDC; receipt verification and provider authorization are coordinated separately; a compiled checkout UI is not proof of a live completed payment.

Runtime import uses **Unity glTFast6.20.0**, official stable registry release2026-08-27, Unity6000.0 minimum, Apache2.0.7.0.0-exp.1 is newer but experimental. Registry/source verified before adding the pinned dependency; existing Burst/Collections/Mathematics versions already satisfy it. The loader rejects external URI references, unsupported extensions/animations, oversized embedded-image dimensions, hash/manifest mismatch, renderer/triangle/texture budget violations and missing/invalid humanoid mappings. It preserves the generated base-color texture on the game's existing matte URP material. It does not overwrite a stock asset or hide a failed result behind a stock character.

Accepted owner-scoped templates use leases: cloned actors retain their imported meshes/textures until destruction, even if account changes retire the template. The cache retains one prepared appearance; unaccepted previews cannot enter its playable route. Character creation includes an optional `likenessJobId` separate from the original seven look IDs, bound into the persisted request hash. `/me` captures that ID into `PlayerProfile`; startup restores its owned manifest/result before entering the world. Asset failure returns through the existing retry flow. The podium agent owns strict factory/preview/world hooks; the coordinator owns creator draft and selection hooks.
