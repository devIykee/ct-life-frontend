# CT Life playable-loop audit — 2026-10-06

[Inference] This is a source audit with proposals, not a claim that the connected game was played end to end. The native visual-review path uses sample profile data and rejects mutations. The separate backend checkout was inspected read-only; its source is not proof of what staging currently runs. All six phases, including ORE and SKR, remain in scope.

**Finding:** the frontend exposes a Phase 1 city shell and several real API entry points. Most later-phase phone apps are placeholders. The most complete repeatable action is **work one career shift → submit the score → receive server-confirmed Game Cash**. Needs can then be restored, but the current config makes those actions free; this is not yet a spend/earn economy loop.

## Strongest immediate gameplay candidate

[Proposal] **“Mod desk: keep the chat alive.”** Ten original fictional CT community messages arrive in a tidy inbox. The player decides whether each violates an explicit rule, with short explanations: support asking for a seed phrase is a ban; a sceptical chart question is allowed; off-topic repeated shilling is spam; disagreement alone is allowed. The joke comes from believable situations and the player's judgment, without real-person accusations or rewarding blind positivity. Forty-five seconds creates pressure; touch targets stay in fixed readable positions. Both controls look equally actionable, so colour does not give away the answer. A balanced deck makes the available score identical between runs.

[Proposal] Keep the existing server ID, duration and score cap. Show local **decisions correct**, then **waiting for shift settlement**, then actual `payCents`/`xp` from the completion response. A lost response must not become a success receipt. Use the existing idempotent HTTP transport for a given completion attempt; no custom cash/XP writes. “Return to city” closes the task; an optional needs action comes afterward and is described as recovery, not spending.

Backend-source limits: `server/application/shifts.ts:40` keeps shifts in memory; `:74` always uses level 1; `:124` persists the cash ledger; `:137` returns XP but this method does not persist it or promote. These are integration facts for the backend owner, not permission to edit that repo. No live shift was started by this audit.

## What offline review proves

`App/Review/ReviewTransport.cs:40` supports sample `GET /me` only; `:47` rejects all other operations. It can prove appearance, input hit targets and a deliberately launched local mini-game practice path. It cannot prove sign-in, paid shifts, earned balance, leaderboard rankings, population, voice connectivity or payment settlement. Any practice entry must be explicitly labelled and must never submit a score or generate a pay receipt. Native import, gameplay observation, Seeker readability/performance and connected backend acceptance remain separate checks.

## Pumpville comparison and demand limitation

Solana Mobile's official [Monolith winners announcement](https://solanamobile.com/blog/solana-mobile-monolith-hackathon-winners-announced), dated 14 July 2026, lists Pumpville among the grand-prize winners and describes native Seeker social multiplayer with exploration, gathering, trading and battles. Pumpville's first-party [About Pumpville](https://pumpville.gitbook.io/docs) describes a shared persistent world and several activities, while its development note explicitly mixes live and planned features. Both pages were opened on 6 October 2026; neither page is independent playtesting or a retention/revenue report.

[Inference] “A social world on Seeker” is already a competitive category. It is not an unmet-need claim or a defensible distinction by itself. The useful distinction to test is recognisable CT situations, expressive characters, shared incidents and activities people choose to revisit. **No primary source examined establishes demand, retention, conversion, advertiser spend or virality for CT Life.** Hosted opt-in playtests and measured repeat visits are still required; a hackathon award for another game does not supply that evidence.
