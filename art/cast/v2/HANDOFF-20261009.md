# Cast v2 continuation handoff

The catalogue now describes the files that exist. It is not a shipped backend catalogue and does not replace the working Unity cast.

## What exists

Seven distinct bases: `ubc_m`, `ubc_f`, `hero_tactical`, `hero_gynoid`, `hero_assassin`, `hero_hazmat`, `hero_balaclava`. They have 14 merged default FBXs,41 referenced modular FBXs and 63 fitted accessory FBXs. One older unreferenced `ubc_f__body.fbx` remains in place, bringing the physical total to 119. All 28 PNGs are 1024×1024; the earlier 512 crowd atlas claim was a target, not existing files.153 files are referenced by the refreshed inventory; 154 physical base-output files were preserved.

The UBC male has four hairstyles and one beard; female has four hairstyles and no beard. Cross-fitted hairstyles are separate receiving-base exports, not permission to attach one base's original geometry to another skeleton. The five heroes have four body partitions each and no interchangeable hairstyle library. Every base has nine fitted accessories and eight sided sockets. No new clothing shapes or cross-base clothing swaps are declared.

Use `export/runtime_part_map.json` for exact per-base FBX paths/hashes, complete head assembly, style replacement, facial-hair addition, material inputs and sockets. Use `export/manifest_v2.json` for imported triangle counts, palettes, budgets and retained errors. `customizer_schema.json` is explicitly a local art-selection proposal, with an example that references real UBC parts. It is not the server Look format.

Pure parsing of the binary FBXs with the installed Blender reader confirms exactly 3 repeated triangle index sets in assassin LOD2 and 2/4 in tactical LOD1/LOD2. The old 03:23 validation/manifest and scripts are retained in `cast-reconcile/before`. The new validator now fails non-normalized weights, which the old validator only reported. ## Runtime and wire boundary

The current contract has seven opaque string fields: `skinTone`, `headId`, `hairId`, `topId`, `bottomId`, `shoesId`, `accId`. There is no established alias for any of these seven new art bases in either current CharacterRegistry or CreatorLookCatalog, and none in the item catalogue. The map therefore leaves all wire aliases null. Local backend permissive handling of unknown IDs is not a validated catalogue agreement.

Current UI `skin_01`…`skin_10` IDs have different hex values from this export. Preserve the existing UI unless an explicit palette migration is reviewed. UI also collapses left/right shoulder and hand sockets; the art map keeps them separate. Facial hair, all simultaneous accessories, accent and uniform scale have no existing lossless wire representation.

The integrator should first create an exact complete default-look registry entry for each accepted base, with its own Humanoid Avatar, preserving all 24 working looks. Native walk/run/idle/sit and reference-pose checks remain necessary. Modular options then require a complete resolver that binds every part/tint/hide flag and refuses a missing part. A catalogue ID alone must not enable an option or retain an old/default actor when resolution fails.

For modular assembly: use either merged defaults or the selected parts, never both. UBC head is head+eyes+brows. Hair replaces hair; beard adds separately. `feet` maps to Shoes. Use same-base proportions, remap all bones/bindposes, activate one LOD per part, and sum every visible accessory. Many individual accessories already exceed the 1200-triangle LOD2 composition cap; do not advertise all combinations as budget-safe. Accessory FBX has a separate `acc_palette` material; intentional base-atlas rebinding/material consolidation is still required. Existing authored mask channels and preview tint formula are documented, not claimed to be the current Unity shader.

## Tactical remains blocked, including hands

The original spec deliberately removes the source gloves and calls `mitten_hands`. That function creates a bevelled palm box and thumb box for each hand, all rigidly weighted to the hand bone. The blunt silhouettes in before/after previews are these existing placeholders, not a new loss caused by the island exclusion. There is no articulated finger geometry or accepted typing/gesture/contact fit. Do not register this base as production-ready.
